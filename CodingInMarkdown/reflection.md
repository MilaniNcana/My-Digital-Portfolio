# Reflection: Coding in Markdown (STAR Technique)

## S – Situation
As part of my Digital Portfolio assignment for Project Presentation 3 (PRP370S), I was required to build a professional GitHub portfolio using **Markdown**, a lightweight markup language used extensively by developers for documentation, README files, and technical communication. This was my opportunity to present my CV, reflections, and project evidence in a clean, well-structured format that is native to the GitHub platform.

## T – Task
My task was to learn and apply **GitHub Flavoured Markdown (GFM)** to code my entire portfolio — including my CV, reflections, and the main README — directly in Markdown. The portfolio needed to be well-organized, easy to navigate, and visually professional when rendered on GitHub. I also needed to demonstrate that I could use Markdown features such as headings, tables, links, lists, images, and embedded media effectively.

## A – Action
I began by studying the Markdown syntax documentation, focusing on GitHub Flavoured Markdown and its extensions such as task lists, tables, and alerts. I then structured my portfolio repository with clearly named folders for each section (e.g., `CareerCounselling/`, `MockInterview/`, `CV.md`). I coded my CV entirely in Markdown, using tables for structured data like education and references, headings for clear section separation, and inline links for my LinkedIn, GitHub, and portfolio site. For each reflection, I used consistent STAR formatting with Markdown headings (`##`) to ensure readability. I also used relative links in the main `README.md` to connect all sections together, making the portfolio easy to navigate.

## R – Result
The result was a fully coded, professional digital portfolio written entirely in Markdown. Through this process, I developed the following skills:

- Writing well-structured documents using Markdown syntax (headings, bold, italic, lists)
- Creating tables to present structured information clearly
- Using relative links to build navigation between files in a repository
- Embedding media (video) using both Markdown and HTML within a `.md` file
- Understanding how GitHub renders Markdown differently from standard Markdown editors

This experience reinforced that Markdown is an essential tool for any software developer. It is the standard for project documentation, open-source contribution, and professional communication on platforms like GitHub, and I am now confident using it in real-world development workflows.
